## 2. 実装方式

フレームワークなしのHTML/CSS/JavaScriptとJSONです。ビルド不要、npm依存なし。ブラウザ内のlocalStorageへ学習記録を保存します。

- `index.html`：読み込み順とアプリの枠
- `app.js`：画面遷移、文法、音声、設定・学習記録
- `data.js` / `expansion.js`：文法1〜36課（当初の課）
- `advanced.js`：上級の文法37〜47課と、その例文で使う単語・文の組み立て
- `curriculum.js`：文法の章立てと課の並び順（最後に読み込む）
- `readings.js`：文法の読み付け
- `vocabulary.js`：文法例文を「単語」ボタンで分解する辞書
- `structures.js`：日本語の文型・語の役割表示
- `words-app.js`：単語一覧・詳細・カード・テスト・復習・絞り込み
- `word-bank.json`：一般語の元レコード5,000件。スラング語義の元レコードも保持
- `slang-bank.json`：独立した口語・スラング207項目
- `sense-examples.json` / `slang-examples.json`：語義ごとの用例
- `word-topics.js`：23テーマの索引と、テーマに対応する語義番号。23番目の「流行語・新語」と `WORD_TRENDS`（新語／流行語の区別・時期・該当語義）は `scripts/word-trends.json` の手選びリストから作る
- `kana-search.js`：カタカナ検索用索引
- `word-origins.js`：語義ごとの出典付き由来
- `clarity.css`：視認性調整
- `refine.css`：最後に読み込む。検索を最上部に置いたホーム・単語ページのレイアウト（`x-` で始まるクラス）と、文字色のコントラスト調整

CSSは複数ファイルを重ねています。見た目の変更前に読み込み順を確認してください。

## 学習範囲

単語の学習範囲は 基本500・日常1,000・会話3,000・発展5,000・全 の5段階（`dist/words-app.js` の `WORD_LEVELS`）。元の単語リストの学習段階（bucket）を先に、同じ段階の中では頻度と会話コーパス順位で並べた累積範囲。基本・日常・会話は当初からの範囲。発展5,000は元の一般語4,969語すべてと頻度表の上位の追加語で、追加語の多い「全」と分けるために設けた。2026-11-11に一時6段階（入門・初級・初中級・中級・中上級）にしたが分かりにくかったため戻し、保存値の2,000は日常1,000として読み込む。

## 文法の章立て

文法は8章47課。章と並び順は `dist/curriculum.js` の `CURRICULUM` だけで決まり、課のID（学習記録のキー）は変えない。一般的なタイ語教科書の順に、文の土台 → 否定と質問 → 時の表し方（初級）→ 気持ちとお願い → つなぐ・比べる（初中級）→ 文を組み立てる（中級）→ 書き言葉でつなぐ → 表現を磨く（上級）。

- 新しい課はIDを末尾に追加し、`CURRICULUM` のどこかに入れる。`tests/grammar.test.cjs` が、全課がちょうど1回ずつ章に入っていること、例文が登録済みの単語に分解できること、上級の課では例文の読みが単語ごとの読みと一致することを検査する。
- 上級の11課（37〜47）はAIが作成し、別担当のAIが点検したもの。母語話者の確認は入っていない。
- 2026-11-11、อะไรの読みを arài から àrai（อะ が低声、ไร が平声）に直した。

## 辞書検索

画面上部の「辞書」は、学習範囲・テーマに関係なく全語から探し、関連の強い順に並べる（`dictionaryResults()`）。日本語（漢字・ひらがな）、英語、タイ文字、声調付き／なしローマ字、カタカナ発音で検索できる。

- ひらがなは日本語訳の読みと照合する。読みは `dist/ja-readings.js`（`scripts/build-ja-readings.py` で生成）。SudachiPy と pykakasi の読みに加え、両方が日常の読みを出さない熟字訓（明後日→あさって 等）を同スクリプトの `IRREGULAR` で補う。検索専用で画面には出さない。生成には `pip install sudachipy sudachidict_core pykakasi` が必要（アプリとテストには不要）。語を追加・修正したら再生成する。
- ひらがな入力は日本語の訳語を優先し、カタカナ入力はタイ語の発音検索を優先する。

## 3. 現行データの数え方

元の一般レコード5,000件＋スラング207件＝5,207レコードですが、見出しの重複を除くと5,077語です。一般の学習欄はスラングだけの項目を除いて4,969項目です。元データの語義・対応用例はそれぞれ7,624件です。

- `id`：ユーザーの学習記録に使う安定した単語ID
- `th`：タイ語見出し
- `ro`：声調付きローマ字
- `frequency`：1～10。10が高い
- `frequencyEstimated` / `frequencyBasis`：推定かコーパス由来かの区別
- `meanings[]`：各語義。`sourceSense` が元資料の語義番号
- `checked`：アプリの確認状態。未校閲は原則テストから除外
- `speechStyle` / `registerTags` / `isSlang`：文体と一般語・スラングの分離
- `relations` / `relationDetails`：関連語IDと、どの語義の関係か

用例のキーは `単語ID#sourceSense` です。配列の添字ではありません。

## 4. 全件校閲のパッチ形式

対象範囲は一般＋スラングを連結した配列の0始まりインデックスです。

| ファイル | 元レコード範囲 | 対象件数 | 対象語義数 |
|---|---:|---:|---:|
| part-1.json | 0～869 | 870 | 1,572 |
| part-2.json | 870～1739 | 870 | 1,335 |
| part-3.json | 1740～2609 | 870 | 1,253 |
| part-4.json | 2610～3479 | 870 | 1,259 |
| part-5.json | 3480～4349 | 870 | 1,132 |
| part-6.json | 4350～5206 | 857 | 1,073 |

各レコードは `id, th, senses[]`、必要なら `wordPatch` を持ちます。語義の編集は `meaningPatch`、対応用例は `examplePatch` に入っています。`status: needs-source` は追加確認が必要という意味です。

パッチはAIによる個別の編集確認です。人間のタイ語母語話者の認証や、全音声の実聴結果を意味しません。句読点の修正だけのパッチも含みます。

### 固定件数のチェックに注意

### 発音の差分に注意

借用語の末尾sなど、辞書に複数の発音がある語があります。タイ文字の綴り規則だけで発音を一律補正しないでください。カタカナ検索は近似検索であり、発音の正しさを保証する表記ではありません。

## 7. 2万語への拡張

`scripts/source-snapshots/expansion-candidates-20000.json.gz` は候補データで、学習教材ではありません。未登録の候補は14,923語で、英語の語義・別方式のローマ字・タイ語の用例しか持ちません。未確認の候補を公開語数に含めてはいけません。

### 追加の手順（第1回 batch-001 で実施）

1. 候補を頻度表の順位順に選び、100語ずつに分ける（語義の説明がない候補は除く）。
2. `scripts/expansion/SPEC.md` に従って、日本語訳・声調付きローマ字・語義ごとの用例を作る。自信のない語は見送る。結果は `scripts/expansion/batch-XXX/part-NN.json`。
3. `python3 scripts/expansion/validate.py batch-XXX` で機械検証する。エラーは0件にする。「flags」は元資料の読みとの食い違いなどの注意点で、点検者が1件ずつ判断する。
4. `scripts/expansion/REVIEW.md` に従って、作成者とは別の担当が全件を点検する（ok／fix／reject）。結果は `review-NN.json`。
5. `python3 scripts/build-expansion.py` → `build-word-topics.py` → `build-ja-readings.py` → `build-kana-search.py`。点検で合格した語だけが `dist/word-bank-more.json` と `dist/more-examples.json` に入る。集計は `dist/expansion-review.json`。
6. `dist/index.html` の `?v=` を更新し、テストと画面を確認する。

### 守ること

- **元の5,000件（`word-bank.json`）は変更しない。** 追加語は別ファイルで、アプリは存在すれば読み込む。
- **公開IDは `tl-(40000＋頻度表の順位)`。** 作成・点検ファイル内のIDは `tl-(20000＋順位)` だが、スラング帳が `tl-2xxxx` を85件使っているため、公開時に振り替える。IDは学習記録のキーなので、公開後は変えない。
- **学習範囲では元の語の後ろに並べる。** 追加語は `bucket: 20000` で、3,000語までの範囲には入らない。5,000語の範囲は元の一般語4,969語すべてと、頻度表の順位が高い追加語で構成する（`tests/expansion.test.cjs` で固定）。
- **頻度は推定。** 教科書系の頻度表の順位から2〜5を割り当て、`frequencyEstimated: true`・`frequencyBasis: "textbook"` を付ける。会話での頻度ではない。
- **用例の出典を区別する。** 候補源の文をそのまま使った用例は `sourceExample: "newthai-v2.4"`、作成した用例は `thai-steps-batch-XXX`。
- **AIによる作成・点検で、母語話者の校閲ではない。** 点検者の指摘率は低く（第1回は1,000語中、修正18・見送り1）、見落としがある前提で扱う。
- 候補は書き言葉寄りで、文語・改まった語・王室語が約4分の1を占める。区分を正直に付ける。

### 文法の確認テスト（2026-11-11）

### 単語のステップ学習（2026-11-11）

単語ページ（一般の単語）の上部に「ステップ学習」。一般語を学習順（`studyRank`：頻度の高い順）に「1回の語数」（5/10/20）ずつ区切り、カード→確認テストで全問正解すると次のステップへ進む。1日のステップ数（1〜3）、今日の進み、連続日数を表示。記録は既存の `thai-steps-words-v1` に `stepWords`（進んだ語数）・`stepsPerDay`・`today`・`streak` を追加（`sanitizeWordState` で検査し、書き出し・読み込みに含まれる）。「今日の10語から」という文言は使わない（利用者の要望）。

「ステップを始める」は1回の流れで、(1) 復習時期の来た語（最大15語）→ (2) 新しい語を音声・意味・用例で提示 → (3) タイ語→意味で思い出す → (4) 意味→タイ語で答える。間違えた問題は4問後にもう一度出し、正解するまで続ける。終了時、新しい語は1回目で正解なら間隔反復の段階1（翌日に復習）、間違えた語は段階0（すぐ復習）。自動発音は `wordState.autoplay`（失敗しても通知しない）。

**ID の注意：** 頻度表の語は公開時に tl-(40000＋順位) になるため、順位10,000以上の候補を追加すると tl-5xxxx と衝突する。それより先に進む前に、公開IDの番台を決め直すこと（`build-expansion.py` は衝突を検出して止まる）。

## 10. データ再生成用スクリプトの依存

アプリの起動・テストには外部データは不要です。一部の再生成スクリプトは元のTSVや翻訳キャッシュを `/workspace/data` などに置く前提が残っています。元資料の全ダウンロードファイルは同梱していません。再生成の前に入力パスを引数化し、`dist/sources.html` の出典から元資料を準備してください。既存の生成済みJSONと校閲パッチを上書きする前に差分を確認してください。
